# 题库组卷

从自己工作区的已有题库筛选、搭配并保存题集，不需要调用模型。入口：[题库组卷](http://localhost:18180/problem-sets/assemble)。

1. 填写名称和用途，选择纯编程比赛或混合题型，设置各题型数量与每题分值，总题数支持 1–1000。
2. 按标签或知识点名称、关键词、编程题 rating、客观题难度筛选。多个标签按“任一命中”处理，留空不限。
3. 按需避开最近 0–50 套题集中的题目，包括草稿；页面默认回看 2 套。这里排除题目及相同题面，不禁止再次考查相同知识点。
4. 预览各题型的可选数量、选题和缺口。系统优先覆盖不同标签，每类题型内按难度递增排列。“换一批”重新选取，库存较小时可能重合。
5. 保存预览或仅保存已有结果。没有选中任何题目时不能保存；保存后可以增加、移除和调整题目顺序。
6. 缺题不会自动调用模型。需要时，在题集详情填写需求并启动 [自动生成补齐](problem-set-generation.md)，已有题目计入配额。

编程题从已发布且未隔离的题目中选择；客观题支持选择、填空、判断，排除空题面或无答案记录。同一题型的相同题面去重，选择题同时比较选项。组卷不重新运行全部解法与测试数据，下载时仍会校验编程题资产。

## 接口与筛选

| 操作 | 接口 |
| --- | --- |
| 只读预览 | `POST /api/v1/problem-sets/assembly-preview` |
| 保存预览 | `POST /api/v1/problem-sets/assemble` |
| 调整顺序 | `PUT /api/v1/problem-sets/:id/items/reorder` |

预览接收 `config` 和 `filter`。`config` 使用 [题型配额](problem-set-generation.md#创建请求)，筛选器如下：

| 字段 | 说明 |
| --- | --- |
| `tags` | 最多 50 项，每项最多 100 字；任一命中 |
| `keyword` | 最多 200 字 |
| `min_difficulty` / `max_difficulty` | 编程难度 800–3500，按 100 递增；省略时不限于更窄范围 |
| `quiz_difficulty` | 空、`easy`、`medium` 或 `hard` |
| `exclude_recent_sets` | 0–50；API 省略为 0，页面默认 2 |
| `seed` | 最多 128 字节；相同库存、条件和 seed 得到相同预览 |

响应包括选中的 `items`、逐题型的 `requested/available/selected/missing`、`missing_count`、`total_score`。保存请求增加名称和用途，并从预览的每个选中项提交 `id`、`type`、`updated_at`；分值由服务端根据配额赋予，不提交题面或答案副本。

保存时重新核对筛选条件、配额、重复项和源题版本，并在一个事务中保存题集与题目。预览过期返回 `409`，不会静默换题；无效条件返回 `400`。重排请求使用 `item_ids`，必须包含题集全部 item ID，且每个恰好一次。

筛选条件保存在题集的 `generation_config.assembly` 中。后续修改条件不会重新抽取已保存的题目；缺题草稿保留原目标题数，补齐前不能作为完整题集导出。

## 下载与复用

通过题集详情下载 [Qraft 题集包](problem-set-generation.md#题集导出)。JSON 清单保存整套顺序、分区、分值和总分，编程题附 Hydro 子包，客观题附通用表格。

组卷筛选的“避开最近题集”与导出时的近期复用检查是两个步骤。导出遇到知识点或题目复用冲突时先查看报告；仅在主动允许这次复用时传 `allow_reuse=true`，它不会绕过题数和资产检查。

完整字段见 [JSON 结构参考](json-schema-reference.md#13-题集编排对象)，接口见 [API 文档](api-reference.md)。
